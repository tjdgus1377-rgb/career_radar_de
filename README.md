# Career Radar

> 채용공고를 근거로 목표 개발 직무의 기술 수요와 개인의 준비 우선순위를 알려주는 End-to-End 데이터 엔지니어링 프로젝트

## 프로젝트 목표

개발자 취업 준비자가 목표 직무와 보유 기술을 선택하면, 최근 N개월 공고에서 많이 요구하는 기술과 우대사항을 확인하고 다음에 무엇을 준비할지 결정할 수 있는 서비스를 만듭니다.

초기 대상은 **데이터 엔지니어 직무**입니다. 공고 수집, 원본 저장, 정제, 기술 추출, 통계 집계, API, 웹 화면, 배포 및 운영까지 하나의 흐름으로 완성합니다. 백엔드·프론트엔드 등 다른 직무는 이후 확장합니다.

현재는 설계 및 데이터 확보 타당성 검증 단계입니다. 아래 구성은 구현 목표이며 동작 중인 기능을 의미하지 않습니다.

## 사용자 경험과 MVP

1. 데이터 엔지니어 직무와 경력 조건, 분석 기간을 선택합니다.
2. 자신이 보유한 기술을 선택합니다. 계정 가입 없이 사용하는 방식으로 시작합니다.
3. 기술별 언급 공고 수·비율, 확인 가능한 필수/우대 구분을 확인합니다.
4. 보유 기술과 기초 기술의 선행관계를 고려한 준비 우선순위를 확인합니다.
5. 추천 이유와 근거 공고, 분석 기간·표본 수·마지막 갱신 시각을 확인합니다.

초기 서비스는 세 가지 결과를 제공합니다: (1) 최근 기간에 많이 언급된 기술스택 순위, (2) 같은 공고에서 함께 요구된 기술스택 조합, (3) 개인의 보유 기술과 선행 학습 관계를 고려한 다음 학습 우선순위. 상승·하락 추세, 취업 성공 확률, 복잡한 LLM 추천은 후속 범위입니다.

## 데이터 확보 전략

최소 한 개의 이용 가능한 소스에서 분석에 충분한 본문을 확보한 뒤 파이프라인을 구현합니다. 네 소스 동시 연동은 완료 조건이 아닙니다.

| 소스 | 역할 | 현재 확인 및 남은 과제 |
|---|---|---|
| 고용24 | 직무내용·우대사항 본문 확보 후보 | 상세 API 명세 확인. 신청 자격·승인·실제 응답·저장 및 분석 조건 검증 필요 |
| 사람인 | 직무·경력·일정·키워드 보완 | 공개 API에 상세 본문 필드 없음. 하루 최대 500회, 호출당 최대 110건. 실제 키와 응답 검증 필요 |
| 점핏 | 기술 태그·자격요건·우대사항 확보 후보 | 공개 공고에서 항목 확인. 외부 수집용 공개 API는 확인하지 못함. 자동 수집·저장·분석 조건 확인 필요 |
| 원티드 | 자격요건·우대사항 본문 확보 후보 | 공개 공고에서 항목 확인. 전체 공고 수집용 공개 API는 확인하지 못함. 자동 수집·저장·분석 조건 확인 필요 |

robots.txt에서 경로를 차단하지 않는 것만으로 저장·분석·재제공 권한을 확정하지 않습니다. 데이터 소스별 근거와 검증 상태는 [데이터 소스 문서](docs/data-sources.md)에 기록합니다.

## 파이프라인과 기술 구성

```text
Airflow: 정기 실행 / 작업 의존성 / 재시도 / 실행 상태
    ↓
이용 가능한 채용정보 API 또는 수집이 허용된 공개 공고
    ↓
Python 수집기 → 원본 저장소 (초기 로컬 파일, 배포 시 객체 저장소 검토)
    ↓
검증 / 정규화 / 중복 제거 / 변경 버전 관리
    ↓
PostgreSQL: 공고 / 기술 사전 / 추출 결과 / 실행 기록
    ↓
기술·우대사항 추출 → 최근 N개월 SQL 집계
    ↓
규칙 기반 준비 우선순위 → FastAPI → Svelte 웹 화면
```

| 영역 | 계획 |
|---|---|
| 언어·패키징 | Python 3.12+, pyproject.toml |
| 수집 | Python HTTP 클라이언트, 출처별 어댑터 |
| 오케스트레이션 | Apache Airflow |
| 저장·분석 | PostgreSQL, SQL, 원본 JSON/HTML 파일 |
| 서비스 | FastAPI, Svelte |
| 실행·배포 | Docker Compose, 배포 환경은 추후 결정 |
| 품질 관리 | pytest, Ruff, GitHub Actions |

Airflow는 주기적 배치 갱신을 담당합니다. 초기 수집 주기는 1일 1회로 시작하는 설계안이며 실제 공고량·정책·호출 예산을 확인해 확정합니다. 비즈니스 로직은 Python 패키지에 두고 DAG에는 작업 연결을 둡니다.

## 수집 범위와 분석 원칙

- 최소 수집: 공고 ID, 제목, 기업, 직무, 경력, 등록·수정·마감 정보, 원문 URL, 직무내용, 자격요건·우대사항, 키워드. 제공되지 않는 값은 결측으로 유지합니다.
- 운영 메타데이터: 출처, 최초·최종 수집 시각, 원본 위치, 본문 해시, 실행 ID 및 추출 규칙 버전.
- 기간은 공고 등록일 기준으로 계산합니다. 최초 수집일을 등록일로 대체하지 않습니다. 실제 확보한 기간만 제공합니다.
- 기간 내 마감 공고도 허용된 보관 범위에서 수요 집계에 포함하고, 현재 지원 가능 여부는 별도로 표시합니다. 조회 결과에서 사라졌다는 이유만으로 마감을 확정하지 않습니다.
- 동일 기술은 한 공고당 한 번 계산하고 동의어를 통합합니다. 출처 간 동일 포지션은 검증된 중복 그룹으로 집계합니다.
- 비율의 분모는 해당 기간·직무·경력 조건에서 **본문 분석 가능한 고유 공고 수**입니다. 키워드만 있는 공고는 본문 기반 통계와 구분합니다.
- 공고 요구 빈도는 데이터에서 계산하고, 학습 선행관계는 별도 관리한 규칙으로 제안합니다. 빈도가 높다는 이유만으로 학습 순서를 단정하지 않습니다.
- 분석 기간, 출처, 표본 수, 본문 확보율, 마지막 성공 갱신 시각과 표본 한계를 표시합니다. 국내 전체 시장을 대표한다고 주장하지 않습니다.

## 구현 순서와 완료 조건

- [ ] 소스 한 곳의 접근·이용 조건과 실제 본문 확보 가능성 검증
- [ ] 실제 공고 수십 건 수집 → 원본 저장 → PostgreSQL 적재 → 기술 빈도 조회
- [ ] 재실행 안전성, 변경 감지, 품질 검사, 원본 재처리 구현
- [ ] Airflow 정기 실행·재시도·실패 복구 및 호출 예산 관리
- [ ] 기술 사전 매칭과 자격요건/우대사항 분리, 근거 문장 저장
- [ ] 최근 N개월 기술 빈도 순위와 명확한 동시 요구 조합 집계 구현
- [ ] 보유 기술 기반 규칙형 준비 우선순위 구현
- [ ] FastAPI와 Svelte에서 조건·보유 기술 입력 및 결과 조회
- [ ] 파이프라인·서비스 배포, 갱신 상태 관측, 운영·복구 절차 문서화
- [ ] 실제 수집부터 갱신된 웹 결과까지 End-to-End 확인

## 저장소와 개발 환경

```text
README.md
docs/requirements.md       # MVP에서 만들 기능과 데이터·운영 기준
docs/plan.md               # 단계별 구현 순서와 완료 조건
docs/data-sources.md       # 소스별 제공 범위·제약·검증 기록
docs/adr/                  # 아키텍처 결정 기록
src/career_radar/          # 수집·정제·추출·집계·API 구현 위치
tests/                     # 핵심 데이터 처리 검증
pyproject.toml             # 현재 기본 패키징과 개발 도구 설정
.env.example               # 비밀값 없는 환경변수 예시
```

Airflow DAG, 프론트엔드, 배포 설정은 해당 구현 단계에서 추가합니다. 현재 프로젝트 의존성에는 서비스 실행 스택이 아직 설치 대상으로 등록되어 있지 않습니다.

```bash
python -m venv .venv
source .venv/bin/activate  # Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
```

API 키와 DB 비밀번호는 Git에서 제외한 환경변수 또는 비밀 저장소에 보관합니다. 원본 공고는 출처의 허용 범위와 보존 정책에 따라 관리하고 공개 저장소에 올리지 않습니다.
