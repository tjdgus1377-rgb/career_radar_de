# Career Radar — 요구사항 정의서

- 갱신일: 2026-11-04
- 상태: MVP 초안. 실제 소스 승인 및 샘플 본문 검증 전
- 초기 대상: 데이터 엔지니어 직무의 국내 취업 준비자

## 목적

최근 채용공고의 자격요건과 우대사항에서 기술명을 찾아 빈도를 보여주고, 한 공고에서 함께 요구되는 기술과 개인이 다음으로 공부할 기술을 알려줍니다.

## MVP가 제공할 결과

1. 선택한 기간·직무·경력 조건의 기술 언급 순위와 비율
2. 같은 공고 항목에서 명확히 함께 요구된 기술 조합
3. 개인 보유 기술과 요구 빈도, 필수/우대 구분, 간단한 선행 학습 규칙을 이용한 공부 우선순위

계정과 이력서 없이 보유 기술을 선택해 결과를 봅니다. 다른 직무, 추세 분석, 자동화된 자연어 이해/LLM 추출은 이후 범위입니다.

## 첫 버전 추출 방식

- 자격요건·우대사항 문장을 항목별로 분리합니다.
- 표준 기술명과 별칭을 담은 작은 사전을 만들고, 본문에서 사전 문자열을 찾습니다.
- 각 매칭에 공고 ID, 항목 유형, 원문 문장, 표준 기술명, 사전 버전을 기록합니다.
- 한 공고에서 같은 기술은 한 번만 집계합니다.
- 같은 항목에서 “Python과 SQL”처럼 명확히 같이 요구하는 표현만 조합 통계에 넣습니다. `A 또는 B`, `A/B`, `A, B 등`은 대안일 수 있으므로 조합으로 만들지 않습니다.
- 직무연수, 도메인 경험, 커뮤니케이션은 기술스택 순위와 구분합니다. 첫 버전에서는 기술 스택 통계에 포함하지 않습니다.
- 사람 검토 표본으로 사전의 누락·오탐을 확인하고 별칭을 추가합니다. 문장 전체를 이해하는 AI를 사용한다고 가정하지 않습니다.

## 기능 요구사항

| ID | 기능 | 완료 기준 |
|---|---|---|
| FR-01 | 데이터 소스 확인 | 최소 한 출처의 접근·저장·분석 조건과 응답 본문을 확인한다. |
| FR-02 | 공고 수집 | 출처별 ID·제목·직무·경력·등록일·수정일·원문 링크와 제공되는 본문을 수집한다. 호출 한도를 지킨다. |
| FR-03 | 원본 보관·재처리 | 이용이 허용된 원본과 수집 메타데이터를 저장하고 같은 데이터로 재처리할 수 있다. |
| FR-04 | 중복·수정 처리 | `(출처, 공고 ID)`를 기준으로 중복을 막고 수정된 내용은 갱신 또는 버전으로 남긴다. |
| FR-05 | 항목 분리 | 자격요건과 우대사항을 나누고 원문 문장을 보존한다. |
| FR-06 | 사전 기반 기술 추출 | 사전·별칭에 맞는 기술을 표준명으로 저장하고 원문 근거와 항목 유형을 제공한다. |
| FR-07 | 기술 빈도 | 최근 N개월 공고별 고유 기술을 세고 공고 수·비율·분모를 제공한다. |
| FR-08 | 기술 조합 | 같은 공고의 같은 항목에서 명확하게 함께 요구한 기술 조합만 집계한다. 대안 목록은 조합에서 제외한다. |
| FR-09 | 학습 우선순위 | 보유 기술을 제외하고 요구 빈도·필수/우대·관리된 선행관계를 이용해 다음 학습 항목과 이유를 보여준다. |
| FR-10 | Airflow 배치 | 수집·추출·집계를 예약 실행하고 실패 재시도·재실행·실행 기록을 제공한다. |
| FR-11 | 결과 화면/API | 기술 순위·조합·우선순위와 기간·표본 수·출처·갱신 시각·근거 공고를 확인한다. |
| FR-12 | 배포 | 수집부터 화면 갱신까지 한 배포 환경에서 동작하고 실행·복구 절차가 문서화된다. |

## 데이터와 계산 규칙

기술 요구 비율은 해당 조건에서 기술을 포함한 분석 가능 고유 공고 수를 분석 가능 고유 공고 수로 나눈 값입니다. 같은 기술이 한 공고에 여러 번 나와도 한 번 셉니다. 키워드만 있는 공고와 본문을 분석한 공고는 같은 분모에 섞지 않습니다.

기술 조합 수는 같은 공고의 같은 자격요건 또는 우대사항 항목에서 두 기술이 명확히 함께 요구된 고유 공고 수입니다. 조합 비율을 함께 제공할 경우 분모를 화면에 명시합니다. 단순히 한 공고 안에 기술 두 개가 있다는 이유로 모든 쌍을 조합으로 만들지 않습니다.

최근 N개월은 실제 공고 등록일로 계산합니다. 과거 데이터가 없으면 수집 시작 이후 기간만 제공하고 실제 분석 범위를 표시합니다. 신입과 경력 3년 이상 공고를 구분합니다. 신입 결과에서 경력 공고를 조용히 합산하지 않습니다.

준비 우선순위는 통계적 취업 성공 예측이 아닙니다. 기술 요구 빈도와 항목 위치, 사용자가 선택한 보유 기술, 작고 검토 가능한 선행 학습 규칙으로 설명합니다.

## 최소 저장 항목

- 공고: 출처, 외부 ID, 제목, 기업명, 직무, 경력, 게시/수정/마감일, URL
- 원문: 자격요건, 우대사항, 전체 설명 중 접근 허용된 텍스트와 원본 위치
- 실행: 수집시각, 배치 ID, 신규/수정/실패 건수
- 추출 결과: 공고 ID, 표준 기술, 항목 위치, 근거 문장, 사전 버전
- 개인 입력: 세션 중 선택한 보유 기술 (초기에는 장기 저장 불필요)

## 운영 기준

- 하루 1회는 초기 스케줄 후보이며 실제 수집량과 정책 확인 후 확정합니다.
- 중첩 기간 재조회와 ID upsert를 고려해 재실행해도 중복 집계하지 않습니다.
- 일부 실패가 정상 집계를 덮어쓰지 않도록 마지막 성공 결과를 보존합니다.
- API 키와 사용자 비밀값을 코드·로그·원본 샘플에 기록하지 않습니다.
- 표본이 부족하거나 본문 분석이 불가능하면 순위·추천을 과장하지 말고 표본 수와 한계를 표시합니다.

단계별 작업과 산출물은 [plan.md](plan.md)에 기록합니다. 소스별 실제 제공 필드와 이용 조건은 [data-sources.md](data-sources.md)를 기준으로 관리합니다.
